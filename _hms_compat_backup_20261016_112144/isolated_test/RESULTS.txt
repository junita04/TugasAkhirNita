HASIL PENGUJIAN TERISOLASI - KOMPATIBILITAS HIVE METASTORE 3.1.3
===============================================================
Tanggal        : 2026-10-16
Tujuan         : Menguji apakah HMS 3.1.3 (dengan klien Hive 2.3.9 milik Spark 3.5.3)
                 kompatibel dengan (a) skema metastore 4.2.0 yang aktif sekarang, dan
                 (b) skema metastore 3.1.0 hasil inisialisasi ulang (re-init).
Sifat          : Serba-ganti (throwaway). TIDAK menyentuh HMS produksi, DB metastore
                 produksi, konfigurasi Docker aktif, maupun tabel Iceberg produksi.
Artefak        : hive-site-313-test.xml, hive-site-313-fresh.xml, hms313_test.py,
                 hms313_fresh_test.py, RESULTS_fresh_schema_313.txt (keluaran mentah).

LINGKUNGAN UJI
--------------
- HMS uji          : apache/hive:3.1.3 (Java 8)
- PostgreSQL uji   : postgres:16-alpine (throwaway)
- Klien uji        : Spark 3.5.3 / Hive client 2.3.9 / Iceberg 1.5.2 (airflow-scheduler image)
- Driver Postgres  : postgresql-42.7.4.jar (driver 9.4 bawaan gagal: "am.amcanorder does not exist" pada PG16)
- Modul tambahan   : hadoop-aws-3.1.0.jar + aws-java-sdk-bundle-1.11.375.jar (HMS 3.1.3)
- Warehouse uji    : s3a://warehouse/hms313-compat (MinIO; namespace terpisah dari produksi)

---------------------------------------------------------------
FASE 1 - HMS 3.1.3 DI ATAS SKEMA 4.2.0 (DB salinan `metastore`)
---------------------------------------------------------------
DB salinan dibuat dari metastore_dump.sql (pg_dump produksi, VERSION=4.2.0,
63 tabel, 9 DB, hanya database "metastore").

Hasil:
  [OK]   list_namespaces  -> bronze/silver/gold/feature_store/qa_*/hmscompat_*/default
  [OK]   show_tables_prod_bronze -> 10 tabel bronze produksi terbaca
         (membuktikan metode thrift get_table_objects_by_name yang gagal di HMS 4.2.1
          kini BEKERJA pada HMS 3.1.3)
  [FAIL] write + commit (Iceberg createOrReplace) :
         org.apache.thrift.TApplicationException: Internal error processing lock
         org.apache.thrift.TApplicationException: Internal error processing show_locks
         org.apache.iceberg.hive.LockException: Failed to find lock for table ...
  [FAIL] read tabel produksi via Spark (metadata_location berskema s3://):
         org.apache.hadoop.fs.UnsupportedFileSystemException: No FileSystem for scheme "s3"
         (sebab: sesi Spark hanya memetakan fs.s3a.impl, bukan fs.s3.impl)

Akar masalah Fase 1 (dari /tmp/hive/hive.log pada HMS 3.1.3):
         org.apache.hadoop.hive.metastore.api.MetaException: Unable to select from
         transaction database org.postgresql.util.PSQLException:
         ERROR: relation "hive_locks" does not exist
         at ...TxnHandler.showLocks(TxnHandler.java:2304)
  => Skema 4.2.0 (buatan Hive 4.2.1) menyimpan tabel txn/lock sebagai NAMA HURUF BESAR
     ter-quote ("HIVE_LOCKS", "NEXT_LOCK_ID"), sedangkan TxnHandler Hive 3.1.3 memakai
     SQL huruf kecil tanpa quote (hive_locks). Karena Postgres case-sensitive untuk
     identifier ter-quote, tabel tidak ditemukan.
  => KESIMPULAN: HMS 3.1.3 TIDAK bisa memakai skema 4.2.0 untuk operasi tulis/commit.
     Membaca metadata (ORM JDO) OK, tetapi txn/lock (raw SQL) GAGAL.

---------------------------------------------------------------
FASE 2 - HMS 3.1.3 DI ATAS SKEMA 3.1.0 (re-init, DB salinan `metastore313`)
---------------------------------------------------------------
DB baru di-inisialisasi oleh schematool Hive 3.1.3 (IS_RESUME=false).
Verifikasi skema: SCHEMA_VERSION = 3.1.0 ("Hive release version 3.1.0");
tabel lock berhuruf kecil: hive_locks, materialization_rebuild_locks, next_lock_id.

Hasil (lihat RESULTS_fresh_schema_313.txt untuk keluaran penuh):
  [OK]   list_namespaces
  [OK]   create_namespace
  [OK]   write_and_commit (create table + insert, memicu lock()/commit Iceberg)
  [OK]   read_back (count = 3, location s3a://warehouse/hms313-compat/hmsfresh.db/compat_fresh)
  [OK]   register_and_read_prod (register metadata produksi s3://, SELECT count = 37655)
  => Tidak ada error lock/show_locks. Klien Spark 3.5.3 + Iceberg 1.5.2 + HMS 3.1.3
     + skema 3.1.0 = KOMPATIBEL penuh (baca DAN tulis/commit).

CATATAN
-------
- Verifikasi baca tabel produksi (s3://) pada uji di atas memakai pemetaan tambahan
  spark.hadoop.fs.s3.impl=org.apache.hadoop.fs.s3a.S3AFileSystem. backend/spark/session.py
  saat ini BELUM memetakan fs.s3 (hanya fs.s3a). Ini celah konfigurasi terpisah dari HMS
  dan tidak dipakai oleh jalur pipeline (pipeline menulis tabel s3a baru, tidak membaca
  tabel s3:// lama lewat Spark). Trino sendiri sudah memetakan fs.s3 (core-site.xml).

KESIMPULAN
----------
Revert HMS ke 3.1.3 WAJIB disertai INISIALISASI ULANG SKEMA metastore ke 3.1.0
(tidak boleh memakai ulang skema 4.2.0), lalu REGISTRASI ULANG seluruh tabel Iceberg.
Setelah itu operasi Spark -> Iceberg (baca + tulis/commit) kembali normal.
